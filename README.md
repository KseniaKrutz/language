# Stochastic Tokenization Lab

Учебно-исследовательский проект для НИР: стохастические характеристики последовательностей субсловных токенов.

## Что делает проект

1. Проверяет наличие корпусов для выбранных языков в метаданных Leipzig Corpora Collection.
2. Загружает доступные корпуса локально и сохраняет манифест источников.
3. Делит предложения на train/test.
4. Обучает SentencePiece BPE и Unigram токенизаторы.
5. Рассчитывает фрагментацию, условную cross-entropy n-граммных (марковских) аппроксимаций и вариативность Unigram-сегментации.
6. Сохраняет CSV и графики.

## Важные методологические ограничения

- Наличие корпуса для каждого языка не гарантируется. Скрипт не подменяет отсутствующий язык похожим.
- Leipzig Corpora Collection включает корпуса из разных источников и лет. Для итогового исследования обязательно сохранить `data/corpus_manifest.json` и описать неоднородность источников.
- `tokens_per_whitespace_unit` не является сопоставимой мерой количества токенов на слово для китайского и вьетнамского: пробелы не всегда соответствуют границам лексических слов.
- Условная cross-entropy n-граммной модели — эмпирическая аппроксимация, а не доказательство марковского свойства естественного языка.
- SentencePiece sampling реализует вероятностную сегментацию для Unigram; это не означает, что BPE и WordPiece имеют такое же вероятностное распределение.
- В первой версии основной эксперимент ограничен BPE и Unigram. WordPiece можно добавить отдельным контролируемым модулем после фиксации протокола.
- Не публикуйте скачанные тексты повторно. Проверьте условия использования выбранных корпусов и укажите источник в работе.

## Установка (Windows / VS Code)

Откройте терминал в папке проекта:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если PowerShell запрещает активацию окружения, выполните:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

## Порядок запуска

Из корневой папки проекта:

```powershell
python src/04_corpus_inventory.py
python src/01_download_corpora.py
python src/02_prepare_data.py
python src/03_train_and_analyze.py
```

Первый скрипт показывает доступность языков. Второй скачивает корпуса. Третий готовит разбиение. Четвёртый запускает основной эксперимент.

## Быстрый пилот перед полным экспериментом

Откройте `config.json` и временно установите:
- `languages`: English, Russian, German, Turkish, Finnish, Mandarin Chinese;
- `vocab_sizes`: `[8000]`;
- `seeds`: `[13]`;
- `max_eval_sentences`: `1000`;
- `max_ngram_train_tokens`: `50000`;
- `max_ngram_eval_tokens`: `10000`;
- `sampling_repetitions`: `5`.

После успешного пилота верните полный план эксперимента.

## Выходные файлы

- `data/corpus_manifest.json` — происхождение и параметры корпусов.
- `data/prepared_manifest.json` — train/test размеры.
- `models/*.model` — модели токенизаторов.
- `results/metrics_raw.csv` — результаты каждого запуска и порядка модели.
- `results/metrics_summary.csv` — средние значения и разброс по seed.
- `results/markov_cross_entropy.png` — зависимость cross-entropy от порядка.
- `results/token_fertility.png` — сравнение фрагментации.

## Научные определения

Для последовательности токенов `X_1,...,X_n` оценивается n-граммная условная cross-entropy:

`H_k = -1/N * sum_i log2 P_hat(X_i | X_{i-k},...,X_{i-1})`.

Она измеряется в битах на токен. Дополнительно приводится приближённая нормировка на UTF-8 байт исходного текста. Сравнение бит/токен между разными токенизаторами само по себе некорректно, поскольку меняется алфавит токенов.

## Воспроизводимость

Сохраняйте:
- `config.json`;
- `data/corpus_manifest.json`;
- версии библиотек (`pip freeze > environment.txt`);
- модели токенизаторов;
- исходные CSV результатов.

SentencePiece предупреждает, что фиксированный seed не гарантирует идентичные случайные последовательности между всеми версиями библиотек и платформами. Поэтому сохраняйте версии окружения.
